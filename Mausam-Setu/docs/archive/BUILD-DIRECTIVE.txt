===============================================================
CORE PRODUCT THESIS
===============================================================

Do NOT build:

"another weather app."

Build:

"an intelligent weather decision-support homepage."

The fundamental question is:

WHAT DOES TODAY'S WEATHER MEAN FOR THIS USER?

The same underlying weather data should produce different
prioritized information for different users.

Example:

Same weather:

Temperature: 34°C
Humidity: 78%
Rain probability: 15%
UV: 9

Fitness user:
→ Heat warning
→ Best workout window

Traveler:
→ Packing recommendation

Parent:
→ School commute warning

Farmer:
→ Irrigation/rainfall insight

Health-conscious user:
→ UV/AQI exposure guidance

Event planner:
→ Outdoor comfort assessment

This transformation is the CORE VALUE of the product.

===============================================================

Never stop at:

DATA → DISPLAY

The application must convert information into useful,

===============================================================

When an error occurs:

1. Read the complete error.
2. Identify root cause.
3. Inspect relevant files.
4. Fix the smallest correct layer.
5. Re-run the failing command.
6. Run related tests.
7. Check for regressions.
8. Continue until resolved.

Do NOT hide errors.

Do NOT simply suppress warnings.

Do NOT delete functionality to make builds pass.
